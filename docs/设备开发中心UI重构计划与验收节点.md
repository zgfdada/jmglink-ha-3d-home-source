## 1. 文档目的

本计划用于指导“设备开发中心”的全面重构，同时作为后续逐阶段验收清单。重构不仅调整视觉样式，还包括信息架构、交互流程、状态反馈、依赖关系、异常处理和发布逻辑。

重构完成后，设备开发中心应形成以下稳定结构：

```text
设备开发中心
├─ 设备项目
│  ├─ 项目首页
│  └─ 单个设备项目
│     ├─ 1 基础信息
│     ├─ 2 能力与属性映射
│     ├─ 3 运行浮窗配置
│     ├─ 4 3D 外观
│     ├─ 5 控制面板
│     ├─ 6 联调测试
│     └─ 7 发布
└─ 3D 模型资源库
   ├─ 本地模型
   ├─ 在线模型
   ├─ 收藏
   └─ 模型配置
```

一级导航最终只保留：

- 设备项目；
- 3D 模型资源库（本地与在线）。

设计图 `7.png` 中出现的“能力模型库、实体映射库、控制面板模板”不作为一级导航。这些能力应合并到单个设备项目的七步流程或内部复用机制中，以设计图的标注意图和边界规范为准。

### 1.0 现行单入口规范（2026-10-02 用户授权）

用户已明确要求删除旧设备开发中心的前后端专用代码，不再维护旧中心。底部“开发中心”只打开 `device-development-center/`；旧组件、旧样式、旧版专用的克隆及面板/绑定写入 API 已移除。设备平台现有数据、模型文件、户型完整备份、项目导入与新中心使用的 API 仍需保留，不做数据清空或不可逆迁移。家具栏模型预览必须由新组件提供，不能重新依赖旧文件。后续回归以单入口、数据兼容、功能测试和容器健康为准；浏览器视觉验证仍由用户负责。

下述 1.1 节及 N0–N10 双入口条款仅记录重构阶段的历史验收条件，已被本节用户新授权取代，不再作为后续开发阻断条件。

### 1.1 历史阶段规则：旧版冻结与新版隔离（已结束）

N0–N10 阶段曾以 `0.1.5-custom.14` 的原设备开发中心为稳定基线，采用“旧版完整保留、新版隔离开发、双入口并行验收”的方式实施。以下条款仅用于理解历史报告，不覆盖 1.0 节现行规范。

#### 旧版冻结规则

- 原设备开发中心的组件、样式、数据读写和运行逻辑保持完整；
- 不以逐步改写旧组件的方式完成新版重构；
- 不在旧版文件中混入新版页面结构和实验逻辑；
- 旧版继续作为回归基准和紧急回退实现；
- 如确实需要修复旧版缺陷，必须独立记录、独立验证，不得与新版重构混为同一改动；
- 每个验收节点都必须验证旧版模块仍可独立编译和挂载。

#### 新版隔离规则

- 新设备开发中心使用独立目录、独立入口组件和独立样式命名空间；
- 新版组件不得依赖旧版组件内部状态或 DOM 结构；
- 可复用无界面的领域函数、Schema、HA 聚合能力和后端存储，但必须通过稳定接口调用；
- 新增数据字段必须向后兼容，旧版读取时不得报错或丢失原有字段；
- 新增接口优先使用独立命名空间，避免改变旧接口的请求和响应语义；
- 新版 CSS 必须有独立根选择器，不能污染户型编辑器、全屋视图或旧设备开发中心；
- 新版自动保存、撤销记录、联调状态和草稿状态不得写入旧版临时状态。

建议的源码边界：

```text
apps/web/src/app/device-platform-center.jsx       # 旧版冻结实现
apps/web/src/app/device-development-center/      # 新版独立实现
apps/web/src/styles/device-platform.css           # 旧版冻结样式
apps/web/src/styles/device-development-center.css # 新版独立样式
```

最终目录名称可根据现有工程规范调整，但“旧版文件不改写、新版文件独立存在”的边界不得改变。

#### 双入口并行规则

- 原“开发中心”入口在整个重构和逐节点验收期间保持可见，并始终打开旧版设备开发中心；
- 在原入口旁增加“新版中心”入口，只打开隔离开发的新版设备开发中心；
- 两个入口分别挂载各自组件，不使用查询参数或浏览器本地存储作为日常验收入口；
- 新旧入口的状态彼此独立，关闭一个中心不得改变另一个中心或正式运行数据；
- 回退到旧版时不需要迁移或删除用户数据；
- 新版未完成 N10 最终验收前，不得替换或删除旧入口；
- N10 最终验收通过且用户明确授权后，才清理旧入口和旧版代码，并把新版入口调整为正式“开发中心”。

建议的入口关系：

```text
底部开发菜单
├─ 开发中心 → 原 0.1.5-custom.14 设备开发中心
└─ 新版中心 → 隔离开发中的新设备开发中心
```

#### 数据安全规则

- 新版上线前必须使用旧版导出文件完成一次恢复演练；
- 新版写入的数据必须保留旧字段，禁止不可逆原地迁移；
- 若需要升级数据版本，先复制、再迁移，并保留可回退备份；
- 新版功能失败不得导致旧版设备模板、绑定、模型或控制面板无法使用；
- 新版删除共享资源前必须检查旧版引用关系；
- 每个节点验收均包含“切回旧版并读取同一份数据”的回归检查。

#### 节点开发纪律

- 每次只开发一个已授权节点；
- 当前节点完成后停止，提交验收材料，等待用户结论；
- 用户未明确通过时，不提前开发下一节点；
- 节点被退回时只修复该节点范围；
- 每个节点必须提供新版结果、旧版回归结果和双入口挂载验证结果；
- 正式提交时只包含当前节点文件，不混入其他待办项或用户已有修改。

#### 验证职责边界

- 所有视觉效果、布局、动效和交互观感仅由用户在现有正式预览服务中验收；
- Codex 不打开或接管任何浏览器，不以截图或自动化浏览器结果代替用户视觉结论；
- Codex 必须完成代码静态检查、自动化测试、生产构建、后端接口、中间件、数据兼容、双入口隔离和运行容器健康检查；
- 未获得用户明确视觉验收结论时，节点状态保持“待用户视觉验收”，不得自行标记视觉通过。

## 2. 总体验收原则

每个验收节点必须同时满足以下条件：

1. 用户确认视觉结构与对应设计图一致；
2. 交互行为与设计标注一致；
3. 满足边界与异常处理规范；
4. 不破坏现有 Home Assistant 设备发现、实体聚合、服务调用、3D 模型和控制面板运行时；
5. 桌面端、窄屏和 Home Assistant Ingress 下均可操作；
6. 自动化测试、生产构建通过；
7. 不写入 Token、Cookie、HA 地址、账号或绝对路径等敏感数据；
8. 不覆盖用户已有设备平台数据；
9. 当前节点获得用户确认后，才进入下一节点。

### 2.1 验收结果

每个节点采用以下结论之一：

- `通过`：进入下一节点；
- `有条件通过`：记录遗留项后进入下一节点；
- `退回修改`：修复后重新验收；
- `暂停`：保留当前成果，暂不继续。

### 2.2 每个节点的固定交付物

- 对应功能代码；
- 必要的数据结构或接口变更；
- 自动化测试；
- 构建结果；
- 供用户在现有服务中验收的入口及用户视觉验收记录；
- 本节点变更清单；
- 已知限制和下一节点影响说明。

## 4. 技术与数据约束

### 4.1 核心引用关系

```text
HA Device / Entity
        ↓
能力与属性映射
        ↓
标准能力 ID
        ↓
├─ 运行浮窗
├─ 3D 动画
├─ 控制面板
└─ 联调测试
```

运行浮窗、3D 动画、控制面板和联调测试只能引用能力 ID，不能直接持久化依赖 HA `entity_id`。

### 4.2 自动保存

- 文本输入：停止输入 800–1500ms 后保存；
- 输入框：失焦时立即补充保存；
- 下拉选择：选择完成后保存；
- 拖拽和滑块：`pointerup` / `touchend` 后保存；
- 保存期间显示“保存中…”；
- 成功后显示“已保存”；
- 失败时显示“保存失败 · 重试”；
- 离开页面前仍有改动时显示“存在未保存修改”。

### 4.3 步骤状态

不使用百分比表达开发步骤进度。每一步只能是：

- 未配置；
- 配置中；
- 已完成；
- 有问题。

状态由系统自动计算，不允许用户手动修改。

### 4.4 依赖校验

以下操作必须触发依赖校验：

- 修改或删除能力；
- 修改能力 ID 或类型；
- 重新绑定实体；
- 修改枚举值；
- 删除或更换模型；
- 修改控制面板组件绑定。

依赖校验至少返回：

- 受影响页面；
- 受影响组件；
- 严重程度；
- 建议动作。

### 4.5 发布约束

- 已发布版本只读；
- 编辑已发布版本时创建新草稿；
- 单个项目仅保留一个当前草稿；
- 错误阻止发布；
- 警告允许确认后发布；
- 发布包不得包含 HA Token、账号、地址、绝对路径、缓存或联调日志。

## N1：设备项目首页

`0.png`

  - 网格和列表切换；
  - 设备项目卡片；
  - 项目更多操作菜单；

  - HA 在线；
  - HA 离线；
  - 配置异常；
- 草稿或已发布状态保留在项目数据中，不在卡片堆叠大量标签。

### 交互逻辑

- 搜索即时过滤，不改变项目数据；
- 新建操作先创建独立自定义设备项目，N3 基础信息步骤中再配置识别规则和 HA 设备绑定；
- 网格/列表偏好在本地保存；
- “打开项目/继续编辑”进入单项目七步流程；
- 导入设备包先检查格式、版本、模型文件和冲突，再创建项目；
- 删除项目前展示项目名称、版本、发布状态和资源引用；
- 删除操作要求二次确认，不连带删除共享资源；
- HA 设备失联时项目仍保留。

### 异常验证

- 空项目列表；
- 搜索无结果；
- HA 全部离线；
- 导入文件损坏；
- 项目 ID 冲突；
- 导入版本低于本地版本；
- 删除请求失败。

### 通过条件

- 页面结构与 `0.png` 一致；
- 卡片与列表模式均可用；
- 搜索、新建、导入、打开、导出和删除入口完整；
- 删除项目不删除共享模型和面板；
- HA 离线项目不会消失。

## N2：3D 模型资源库与模型配置

### 设计依据

`1.png`、`4.png`

### 实施内容

- 本地与在线模型合并到统一资源库；
- 支持全部、本地、在线、收藏筛选；
- 支持名称、标签和作者搜索；
- 模型卡片展示来源、作者、标签和主要操作；
- 本地模型支持预览、配置、应用到设备；
- 在线模型支持预览、收藏、下载到本地；
- 模型配置页面包含：
  - 模型 ID 与名称；
  - 可选设备模板关联；
  - GLB/自包含 GLTF 上传；
  - 尺寸、缩放和锚点；
  - 摆放位置和离地高度；
  - 材质颜色、金属度和粗糙度；
  - “作为家具”开关；
  - 家具类型和标签；
  - 交互式 3D 预览。

### 交互逻辑

- 模型 ID 创建后不可修改；
- 上传后立即解析模型尺寸并预览；
- 模型文件缺失时保留配置并显示“模型文件不可用”；

## 7. 视觉验收基准

### 7.1 色彩

- 绿色：正常、已绑定、已完成；
- 蓝色：当前选择、主要操作、信息；
- 黄色：警告、需要检查；
- 红色：错误、删除、失效；
- 灰色：未配置、不可用。

### 7.2 页面一致性

- 左侧导航宽度、顶部栏高度、页面内边距统一；
- 卡片圆角、边框、阴影和间距统一；

- 表单标签、必填标记和错误提示统一；
- 普通字段错误显示在字段下方；
- 页面配置问题显示顶部提示条；
- 危险操作使用 Modal；
- 后台保存失败显示右上角“保存失败 · 重试”。

### 7.3 响应式

- 大屏保持设计图的信息密度；
- 中等宽度允许卡片和表单自动换列；
- 窄屏时侧栏收起，步骤导航可横向滚动；
- 控制面板三栏在窄屏按组件库、画布、属性面板顺序堆叠；
- 任何关键操作不得只能依赖 hover。
