# 教程第一部分：安装与首次连接

单个视频，开头对比两种方式。以下每行是建议字幕断句，标题不播读。

## 01｜先选安装方式

先看两种安装方式的区别。  
Home Assistant App，  
适合使用家庭助理系统，  
并且已有应用商店的用户。  
它由 Supervisor 管理，  
安装后自动连接当前 Home Assistant。  
独立 Docker，  
适合把三维家居部署在 NAS、服务器，  
或运行 Docker Desktop 的电脑上。  
它需要在界面中填写家庭助理地址，  
以及长期访问令牌。  
两种方式使用相同项目的已发布镜像，  
提供相同的主要家居功能。  
区别主要是部署位置、连接方式，  
以及数据保存和维护方式。  
没有应用商店的用户，  
可以选择独立 Docker。  
这一集会依次讲解两条路线，  
你只需完成适合自己的一条。

## 02｜安装前准备

开始前，先确认三件事。  
第一，Home Assistant 已经能正常使用，  
需要展示的设备已经接入。  
第二，安装主机与家庭助理之间可以通信。  
独立 Docker 的连接，  
由容器所在的主机发起。  
浏览器能打开家庭助理，  
不一定代表容器也能连接到它。  
第三，准备保存项目与模型的数据位置。  
当前镜像支持两类架构，  
分别是 x86 六十四位，  
以及 ARM 六十四位。  
已有项目先备份，  
再开始调整部署方式。

## 03｜App：添加安装仓库

先看 Home Assistant App 路线。  
进入设置中的应用管理，  
打开应用商店的仓库管理入口。  
不同版本的菜单名称可能略有不同。  
把画面中的完整安装仓库地址复制进去，  
注意保留协议、端口和项目路径。  
这里添加的是安装仓库，  
不是名称带有 source 的源码仓库。  
保存后，回到商店，  
查找 JMGLink HA 3D Home Custom。  
如果暂时没有出现，  
先刷新商店信息，  
再检查仓库地址与网络访问。

## 04｜App：安装、启动、打开

进入应用详情，先执行安装。  
Supervisor 会按主机架构选择镜像。  
安装用时取决于网络和主机性能，  
以实际进度与日志为准。  
安装完成后启动应用，  
检查日志中是否有启动错误。  
随后点击打开 Web 界面。  
App 通过当前家庭助理环境连接，  
通常不需要填写长期访问令牌。  
本路线优先使用应用提供的网页入口，  
不要把 Docker 的八一零一端口，  
当成 App 必须开放的端口。  
如果需要保留方便的入口，  
再按当前应用设置启用侧边栏显示。

## 05｜App：检查首次连接

界面打开后，先检查连接状态。  
目标是显示已连接，  
并且能够读取当前家庭助理的实体。  
接着创建或导入自己的项目，  
再为房间和设备配置绑定。  
空白项目中没有三维设备，  
不等于家庭助理连接失败。  
如果界面能打开，实体却没有同步，  
先检查连接信息和应用日志。  
暂时不要通过反复卸载重装来排查，  
因为卸载可能影响已经保存的数据。

## 06｜Docker：准备部署目录

接下来是独立 Docker 路线。  
前提是 Docker 已安装并运行，  
并且可以使用 Compose 命令。  
先用画面中的版本命令检查环境。  
建立一个固定的部署目录，  
把项目提供的发布版 Compose 文件放进去。  
确认文件名没有多出文本扩展名。  
后续命令都在这个目录中执行。  
本教程素材包附带仓库原始配置，  
可以直接取用。  
使用已发布镜像安装，  
不需要先下载源码，  
也不需要在部署主机上安装开发工具。

## 07｜Docker：读懂关键配置

启动之前，先理解配置中的三个重点。  
第一，镜像地址使用项目发布的镜像，  
并保留配置好的独立运行入口。  
不要随意删除入口设置，  
否则可能进入不适合独立 Docker 的启动方式。  
第二，端口映射左边是主机端口，  
右边是容器内部端口。  
默认使用八一零一访问网页，  
映射到容器内部的八零九九。  
第三，两个挂载目录负责保存数据。  
数据目录保存项目与运行配置，  
素材目录保存用户模型等资源。  
如果是从旧部署迁移，  
先备份并指向原有目录。  
不要让两个容器同时写同一份数据。

## 08｜Docker：拉取并启动

现在开始执行命令。  
先运行拉取命令，下载发布镜像。  
下载时间取决于实际网络，  
看到错误时应先检查原因。  
拉取完成，再运行后台启动命令。  
最后运行状态查看命令，  
确认服务没有退出或反复重启。  
这里展示的是要执行的命令，  
实际结果以你的终端输出为准。  
如果启动异常，  
可以使用画面中的日志命令查看原因。  
不要把命令没有报错，  
直接当成网页和家庭助理都已连接成功。

## 09｜Docker：连接 Home Assistant

容器启动后，  
在浏览器打开主机地址和八一零一端口。  
这里的主机地址，  
是运行三维家居容器的主机地址。  
进入首次连接配置，  
填写 Home Assistant 地址。  
这个地址则是家庭助理本身的访问地址。  
如果家庭助理运行在别的主机上，  
不要把 localhost 当成它的地址。  
接着在家庭助理用户资料的安全页面中，  
创建用于三维家居的长期访问令牌。  
令牌只会显示一次，  
请妥善保存，并在录屏时遮挡。  
把令牌填入对应字段，  
点击保存并连接。  
连接配置保存在后端数据目录，  
所以持久化目录必须保留。

## 10｜两条路线的统一验收

无论选择哪条路线，  
最后都检查三个结果。  
第一，网页可以正常打开。  
第二，连接面板显示已连接。  
第三，可以读取真实实体及其状态。  
三个条件都满足，  
本部分的安装与连接才算完成。  
接下来可以创建一个测试项目，  
先查看状态，再绑定设备。  
真实控制会改变设备状态，  
应在了解操作含义后再测试。  
下一部分，我们再从零建立户型。

## 11｜常见问题：按顺序排查

如果安装过程中遇到问题，  
先判断卡在哪一层。  
网页打不开，  
检查服务是否运行、访问地址与端口映射。  
八一零一被占用时，  
只修改映射左边的主机端口，  
然后用新端口访问。  
网页能打开，但家庭助理未连接，  
检查容器到家庭助理的网络，  
地址、协议和令牌是否正确。  
已连接但没有三维设备，  
继续检查项目、房间和实体绑定。  
升级后还是旧页面，  
确认实际版本，再强制刷新浏览器。  
按层排查，通常比重复安装更容易定位问题。

## 12｜数据保存与下一步

最后，记住安装之外的维护工作。  
较大修改前，导出完整项目，  
并备份运行数据与模型目录。  
Docker 更新时，  
在原部署目录重新拉取并启动，  
保留原来的挂载路径。  
App 更新前也要先备份，  
避免用卸载重装代替升级。  
本教程展示的是操作路径、命令与界面示意，  
不是对你的主机执行安装的记录。  
素材包包含完整配置、操作清单，  
配音和独立字幕，方便暂停对照。  
到这里，安装与首次连接就完成了。  
下一部分，开始创建自己的家。
