## 共同协议

[统一资源协议 v1](资源协议-v1.md) 定义资源身份、版本快照、文件清单、精确依赖与本地绑定分离。协议代码位于 `jmglink-ha-3d-home/source/packages/resource-protocol`，从服务端同名包同步；服务端 `scripts/sync-protocol.mjs --check` 同时检查代码和文档副本，不允许两边独立修改后漂移。

客户端支持五种协议类型：模型（`model`）、只读侧栏控件（`sidebar-widget`）、自定义设备控件或控制面板（`device-control`）、动效（`motion`）和完整设备项目（`device-project`）。可共享的侧栏控件限于无服务动作的 Worker 数据转换控件。设备项目以自包含包安装，随后需在本地重新关联 HA 设备与实体。资源版本与应用版本独立。

## 使用流程

1. 独立部署使用当前源码构建客户端，并设置 `HA3D_RESOURCE_CENTER_URL` 为资源中心 HTTPS 根地址；源码 Compose 已透传此变量。Home Assistant App 源码构建后可在配置中填写 `resource_center_url`。留空时仅使用本地资源。要启用在线功能，必须指定资源中心地址；私有仓库的下载网关由所连接的服务端提供。
2. 重启本地后端，在设备开发中心点击头像进入账号，或在设备项目、模型、控件、面板与动效资源库及侧栏控件库的在线标签浏览资源。侧栏有未保存草稿时需先保存。
3. 点击“登录 / 注册”，打开服务端账号页面注册并验证邮箱，再登录并批准客户端显示的授权码。返回客户端点击“我已批准，检查登录”。授权码有效期 10 分钟，检查间隔最少 5 秒。
4. 在对应的在线列表中查找资源，安装已审核的版本。模型、设备控件及动效进入各自的本地库；面板可在设备项目中选用，完整设备项目需要重新绑定 HA。侧栏控件安装到所选户型和楼层的草稿，须在本地绑定实体、加入页面并发布。
5. 模型和只读侧栏控件在开发界面维护资源介绍、可见版本及预览图，模型同时维护标准品、品牌和型号。模型保存退出、应用到设备，以及侧栏发布到主页或保存退出时自动加入本地持久同步队列；单独保存侧栏草稿、放弃修改不会上传。服务端分配隐藏修订（例如 1.2.0+r.37），普通界面仅显示 1.2.0；内容不变与失败重试不增加修订。所有提交仍需审核，公共库每个资源仅展示最新已通过版本。 账号页查看同步错误和审核意见，可手动重试。资料在开发时保存，后续不再重复填写；标准品须填写品牌和型号，图片默认自动生成（侧栏使用模拟状态）。

6. 要分享自定义设备控件、面板、动效或完整设备项目，在对应卡片或设备项目菜单点击“上传到资源中心”。截图和上传在后台执行，审核结果可在账号页查看。

## 代码入口

| 路径（相对 source） | 职责 |
| --- | --- |
| `apps/server/src/resource-center/ResourceCenter.js` | 设备授权、远端接口、私有会话、导出适配、哈希缓存与安装记录 |
| `apps/web/src/app/resource-center` | 账号连接、分库浏览、自动缩略图、同步状态及审核记录、指定楼层安装、安装记录 |
| `packages/resource-protocol` | 共享协议校验与可移植字段白名单 |
| `apps/server/src/main.js` | 注册功能，沿用访问策略与实例写入门控 |

新增 API 统一位于 `/api/resource-center`。浏览器不获得云端访问 token；本地后端只向配置的资源中心发送账号凭据，资源中心 API 请求禁止跟随重定向。公开 GitHub 附件可在限定的 HTTPS 域名间跳转，而私有仓库文件始终经资源中心网关下载。HTTPS 根地址为正式配置，HTTP 仅限回环开发。所有请求以相对路径发送，兼容 HA Ingress 前缀。

## 安装、绑定与故障恢复

文件全部校验完成后才写入本地库。每个来源、版本和目标侧栏工作区生成确定的副本 ID。重复安装同版幂等；新版独立安装，不覆盖旧版修改与绑定。新副本在安装后单独配置实体绑定。

`HA3D_DATA_DIR/resource-center-private` 保存会话、对象缓存、安装记录和自动资源标识映射 publications.json。会话不加入完整实例导出；资源本身仍由现有模型/侧栏备份机制包含。私有目录属于持久状态，不能作为临时目录清理。迁移完整运行目录时保护其中凭据，切换资源中心后旧会话不会用于新地址。

安装先写 pending 记录，再写资源，最后标记 installed。磁盘失败后重复安装同版会核对副本指纹并恢复记录；目标被改动时拒绝覆盖。网络或字节校验失败不写本地库。主页发布操作仍由用户明确执行。

## 验证与发行

客户端常规测试使用 `npm test`，前端使用 `npm run build`。服务端项目的集成测试以真实 `DevicePlatformStore`/`SidebarStore` 验证完整流程；界面验收使用 Codex 内置浏览器、隔离测试账号和合成户型。

Dockerfile、workspace lock 和 `scripts/package-release.mjs` 均包含协议包。通过当前源码构建可使用资源中心选项；正式安装镜像及版本发布信息仍按主线发布流程更新。

审核由服务端账号网页中的管理员完成，客户端设备令牌没有审核权限。公共列表、版本和下载接口不会向其他用户开放待审核或驳回内容；作者本人也不能通过客户端安装尚未通过的版本。原先“需授予发布者角色”的机制已被统一提交审核替代。

在线模型仅负责发现和安装，复用本地模型卡片、搜索和排序；在线控件直接复用本地库的三栏布局、列宽、间距和全高结构，空库也保留三栏，安装到当前楼层。在线页不显示账号横条和内层功能导航。模型及只读侧栏控件使用上述自动同步流程。账号与提交状态从顶部账号入口查看。

编辑中心按桌面端验收；移动端入口已由产品隐藏，本次及后续同范围调整不要求手机适配或手机验收。

控件库本地/在线来源使用共享分段切换组件，固定在左侧标题与搜索框之间。

模型提交增加“是否标准品”：标准品必须填写品牌和型号（各最多 120 字符），非标准品不携带品牌/型号。信息保存为版本清单的可选 product 字段，参与摘要与审核，并在在线模型及服务端审核卡片展示。旧清单缺少该字段继续有效，不补写或猜测历史商品信息；旧客户端可能拒绝含新字段的清单，需使用本次同版 online 客户端。

## 自动同步实现与验收（2026-11-09，NAS 历史验收）

`resourceSharing` 是本地开发元数据，由共享 schema 验证，保存到模型/控件定义；不进入 portable entry，不包含实体绑定。ResourceCenter 独立同步队列先捕获已保存快照，持久写入私有 outbox 和对象缓存，再上传。队列固定账号与源中心，重试沿用请求 ID；服务端负责修订分配及审核。模型编辑器的保存返回、开发中心关闭和栏目切换均先执行保存，侧栏返回/楼层切换保存草稿并触发同步。明确放弃修改不提交，浏览器直接关闭使用未保存提醒。

当时验收的是模型和无 action 的 Worker 侧栏控件自动同步。自定义设备控件、面板、动效及完整设备已按下文所述接入显式上传流程。历史资源不会因为服务重启而批量分享，安装副本也不会自动再次分享。资料写入或快照准备失败时本地保存仍保留并返回同步错误；网络失败保留任务自动重试。

回归入口：服务端 `npm test`（含自动修订、幂等、离线/重启/账号隔离/顺序）、`npm run test:browser`（合成账号、真实本地路由与 UI），客户端相关模型/侧栏/备份测试和 `npm run build`。真实 PostgreSQL 并发验收可使用服务端 `scripts/verify-postgres.mjs`，本次已在 NAS 的独立临时 schema 执行并清理测试数据。

为避免浏览器尺寸、渲染差异造成空修订，本地内容去重不把自动生成图片本身作为变化；修改代码/模型/资料时新图片随快照上传，手工更换图片则作为内容变化。

本次本地验收结果：服务端 29 项测试、客户端模型/侧栏/备份相关 21 项测试通过；隔离浏览器完整授权、自动同步、审核、安装、开发中心关闭保存和布局验收通过；两仓协议一致。前端生产构建通过。随后曾部署 NAS 联调环境；同日已迁至 Docker Desktop 并移除 NAS 服务，未正式发布版本。

旧只读侧栏控件无需先修改代码：首次保存退出或发布到主页时自动补齐默认资源资料并入队；普通草稿保存不触发补传，无变化的后续退出复用已有提交。DOM 控件及带设备控制动作的控件不自动迁移。

侧栏在退出/发布完成本地保存后，后台生成模拟数据预览图，不依赖是否打开控件编辑页；后台任务不修改草稿修订号。截图失败保留待重试任务，在账号页显示原因，不提交无图版本。已有缺图提交可补传一次带图修订；后续自动截图差异仍不产生空修订。

本机体验环境启用默认用户：未登录个人账号时以 desktop-default 上传，登录后新提交归个人账号，退出恢复默认身份；窗口提供“登录自己的账号”。已有队列的账号归属不随切换而改变，审核流程不变。普通部署默认关闭此配置。

## 已有模型退出同步（2026-11-10）

旧模型不必逐个进入编辑器再保存。退出设备开发中心时会检查已有本地模型，逐个生成实际 3D 预览图，补齐缺失的默认资源资料并加入持久同步队列；从模型库切换栏目时同样执行。模型和侧栏保存完成即可退出，截图与上传在后台进行，不显示全屏遮罩；刷新后续传未完成任务，完全关闭浏览器则下次打开继续。错误与重试入口位于账号页。模型源文件、尺寸、材质及本地 ID 保持原值；已有提交按内容去重。

配置了资源中心才执行退出同步。真正内置只读模型、未主动开启分享的在线安装副本不参与此批处理。请求携带截图对应的模型快照，服务端在入队前及逐个保存时复核，其他终端的修改不会被旧截图覆盖。上传与截图失败均会明确显示，不静默把无图版本提交。

## 用户验收数据隔离与测试重置（2026-11-10）

用户要求自动内测不得占用或污染其后续手工测试。本机体验数据集现已交还用户验收；后续自动测试只使用隔离数据库、账号、存储和端口。

此前 verify-desktop.mjs、verify-model-library-exit.mjs 会向当前本机环境写入数据，现均已改为 run-isolated-browser-check.mjs 的兼容入口，只运行独立 pg-mem/临时文件/测试端口的 browser-smoke 夹具，不连接 18110/18111，也不读取用户 Docker 数据卷。要求显式提供 HA3D_TEST_TMP；测试暂存按全局规则收尾清理。此前目录中的截图和 JSON 是历史验收证据，不代表当前资源中心仍保留这些测试提交。

本次按原验收清单精确删除 17 条 desktop-default 模型提交、17 个队列任务、34 个发布身份映射及相应同步请求；恢复了这 17 个旧模型被测试添加的默认资源资料，保留模型本体、文件、参数和用户账号。移除 40 个无其他引用的服务端对象文件与 41 个本地缓存文件。原 test 账号记录及用户已审核通过的默认天气控件保留。当前没有这些模型的提交或去重记录，用户下一次退出开发中心可重新验证首次上传。

审核列表的撤回将提交标记为已撤回。客户端下次保存或退出时，内容未修改也会创建新的待审核修订；撤回本身不会立即上传。

GitHub 模式下，安装接口会返回额外下载索引；客户端优先从 GitHub 官方附件域名无凭据直下载，逐跳检查 HTTPS 域名并校验文件 SHA256；失败可回退网关。原本地缓存、幂等安装和修改保护不变，旧网关仍兼容。

私有仓库模式：网关只返回 downloads.mode=gateway，客户端不再尝试 GitHub 直下载；仍经原文件接口和摘要校验安装，GitHub Token/签名 URL 不进入客户端。当前测试和正式仓库均私有，验收环境只连接测试仓库。
