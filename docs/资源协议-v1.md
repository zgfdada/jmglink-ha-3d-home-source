# 3DHome 在线资源协议 v1

状态：当前实现契约。协议版本 `ha3d-resource-v1`；服务端版本 `0.1.0`。本文是服务端与客户端的共同开发依据，变更必须同步客户端协议副本与契约测试。

## 1. 边界与资源类型

`online/server` 是独立在线资源中心；`online/client` 是现有 3DHome 完整客户端，包含本地后端。资源中心不连接用户 HA，不保存家庭实时状态，不替代本地后端。

统一类型：`model`（3D 模型）、`sidebar-widget`（侧栏控件）、`device-project`（设备模板）、`device-control`（设备面板控件）、`motion`（动效）。上述五类均支持发布、审核和独立本地安装。设备面板控件包含单控件与完整控制面板两种入口；完整设备使用自包含包，携带模型、面板、能力定义与部件动效快照。

## 2. 包格式

传输由 JSON 清单与独立二进制对象组成，不接受任意 ZIP 解压路径。文件按 SHA256 内容寻址；清单使用稳定键排序的 JSON 计算摘要，数组顺序保留。文件哈希针对原始字节。

```json
{
  "format": "ha3d-resource-v1",
  "resource": "alice/weather-card",
  "type": "sidebar-widget",
  "version": "1.0.0",
  "parent": null,
  "name": "天气概览",
  "description": "绑定一个天气实体即可使用。",
  "license": "GPL-3.0-only",
  "changelog": "首次发布",
  "compatibility": {"protocol": 1},
  "entry": "widget.json",
  "files": [
    {"path": "widget.json", "sha256": "64位小写十六进制摘要", "size": 1024, "mediaType": "application/json"}
  ],
  "dependencies": [],
  "bindings": [{"key": "primary", "kind": "entity", "domains": ["weather"], "multiple": false, "required": false}],
  "permissions": ["entities.read"]
}
```

客户端按服务端、账号、类型和本地资源身份持久保存自动 UUID 标识（`publications.json`）；改名、编辑及后续版本沿用，复制资源使用新标识。旧版手填标识可按唯一相同入口内容继承；无法唯一匹配时生成新身份。UI 不要求用户填写或维护编码。

`resource` 为不可变的 `账号命名空间/slug`，小写字母、数字和连字符；命名空间由认证用户决定，不信任请求中的作者字段。可见版本为无前缀的三段非负整数 SemVer；精确版本允许唯一内部后缀 `+r.N`（N 为 1–999999999）。不接受范围、latest、预发行或其他后缀。内部修订独立于可见版本，按资源全局递增，不能用 SemVer 构建元数据的相等规则代替精确身份。单个资源类型固定。首版 parent 为 null，后续版 parent 为已有版本的**清单哈希**。同一版本不可覆盖；相同版本和相同摘要重复提交返回已有发布结果。资源许可保存在清单中；客户端开发界面明示使用 GPL-3.0-only，上传不再要求重复填写表单。

可选 `preview` 指向 `files` 中不超过 512 KiB 的 PNG/JPEG。模型复用本地缩略图；侧栏用隔离沙箱和模拟状态截图，不读取真实实体。作者可替换图片。预览对象参与摘要和不可变版本，读取仍需认证：作者可查看自己的待审图，审核员使用网页专属预览接口，其他账号只可查看已通过版本。旧版本无预览字段时显示明确缺图提示，不修改原清单或摘要。

文件路径为大小写不敏感唯一的相对 POSIX 路径，拒绝绝对路径、反斜杠、空段、`.`、`..`、Windows 保留名、控制字符和冒号。服务端磁盘只按哈希存储，客户端同样不把逻辑路径作为文件系统路径。

第一阶段限制：每包最多 32 个文件、总计 32 MiB、单对象 16 MiB、入口 JSON 1 MiB；最多 16 个直接依赖、64 个依赖节点、8 层深度。账号默认对象额度 256 MiB，HTTP 请求和登录尝试另有限流。小型 JSON 文件仍保存完整快照，不使用 JSON 补丁链。

模型入口 `{ "format":"ha3d-model-v1", "model":{...}, "asset":"model.glb" }`；asset 为 null 时只允许客户端支持的程序化模型。文件模型只接受自包含 GLB 2.0 或自包含 glTF 2.0，不能引用外部 URL/相对外部文件；入口不含本地 ID、source.url、设备、位置或实体绑定。模型资产与渲染配置同版。

侧栏入口 `{ "format":"ha3d-sidebar-widget-template-v1", "widget":{...} }`；widget 保存展示与逻辑字段，实体与身份字段必须为空/不存在，导出使用字段白名单。第一阶段只支持 `scriptMode=transform`、无设备服务 action 的只读控件，使用现有 Worker 和沙箱渲染通道。交互控件不能通过修改权限字段绕过限制；服务端和客户端双重拒绝。

### 控件、面板、动效和完整设备（2026-11-11）

| 类型 | 入口 | 本地安装 |
| --- | --- | --- |
| device-control / control | control.json，ha3d-device-control-v1，kind=control | 自定义控件库，内联 UI 和默认属性 |
| device-control / panel | control.json，ha3d-device-control-v1，kind=panel | 独立面板模板及逻辑能力槽位 |
| motion | motion.json，ha3d-motion-v1 | 自定义动效库，参数、JavaScript / GLSL 快照 |
| device-project | device.json，ha3d-device-project-v1 | 独立设备项目、模型与面板；上传模型字节另存为包内对象 |

新增入口复用客户端实际 schema 归一化，服务端使用 scripts/build-device-schema.mjs 生成的纯 schema 包；修改 schema 后重新生成并同步协议副本。服务端与客户端均拒绝归一化后仍不相同的结构、额外家庭绑定与未知字段。保留逻辑 capabilityId、控制动作定义与动效快照，剥离实体、设备、账号、凭据、本地 URL、时间戳和本机资源身份。代码、名称和说明中的任意硬编码内容仍需要作者检查。

新增类型的 manifest.bindings 与 permissions 均为空。能力槽位是设备模板内部定义，不是实际家庭实体。在线预览使用本地模拟数据和现有控件/动效/模型组件，不连接 HA。完整设备的引用在导入时重新分配；安装不自动匹配家庭设备，也不发布到主页。

上传先捕获不可变快照和实际缩略图，在入队时复核来源摘要及账号；出站任务持久化、按内容去重，撤回后的相同来源可重新提交修订。安装使用来源及清单摘要生成稳定身份；重复安装保留本地编辑；中断后重试先核对本地内容，发现修改即停止。私有 GitHub 模式继续经网关下载与摘要校验，不向客户端下发 GitHub 凭据。

## 3. 版本、依赖与增量

发布者先上传文件，再提交完整清单。文件已在**当前账号有权使用的对象集合**中才可跳过上传，不向无权用户暴露哈希存在与否。服务端验证文件大小、摘要、入口内容、权限和依赖后，在数据库事务中保存待审核的不可变清单；提交失败不出现半成品版本。管理员审核通过后才对其他用户公开。未发布上传对象计入额度；第一阶段不运行对象 GC，后续维护工具必须核对引用与保留期，不能清理仍被版本引用的对象。

依赖项格式：`{ "resource":"alice/model", "version":"1.0.0", "manifestSha256":"..." }`。依赖均为确切版本和确切清单哈希。服务端要求依赖已审核通过，检测缺失、循环、同一资源不同版本冲突和超限；客户端再次验证下载清单和完整依赖图。第一阶段安装器不接受非空依赖（完整设备以自包含包接入，不依赖跨资源解析）；服务端已提供依赖图解析接口以固定协议。

所谓增量是**文件级内容去重**：只传缺失对象；改变 GLB 后仍需传输完整新 GLB。不是二进制差分，不承诺 Git merge/rebase。首次安装无需下载历史版本；安装固定版本不随远端新发布自动变更。

## 4. 本地绑定分离

共享清单的 `bindings` 只声明槽位、领域、数量、必需性，不含实际实体 ID。第一阶段侧栏只有 `primary` 槽位，模型没有槽位。

禁止上传 HA 地址、Token、账号密码、设备 ID、区域 ID、实际实体 ID、家庭状态和历史、用户别名映射。结构字段白名单和已知凭据/本地绑定字段检查不是任意代码的脱敏证明：代码、描述中可能含作者硬编码的私密信息，提交前需展示图片并由发布者确认其已检查代码、文案与隐私；无需 JSON 清单预览步骤。含硬编码实体访问的代码不具备可移植性，应改为绑定槽位读取。

客户端本地安装记录：`installationId`、服务端来源、资源身份、版本、清单摘要、安装副本 ID、初始内容摘要、安装时间。真实实体选择继续由本地编辑器保存。安装不自动发布到主页、不自动授权设备控制。

第一阶段每个版本安装为独立副本；同版重复安装幂等。新版安装不会覆盖已修改的旧版，也不自动迁移实体绑定或页面引用。更新替换、保留绑定、三方比较和一键回退到第二阶段；此时用户可通过保留的旧副本切回。摘要或内容校验失败不修改本地库。

## 5. 账号与授权

服务端负责注册、邮箱一次性验证、登录与退出。密码使用 scrypt 随机盐，验证令牌、会话和设备授权凭据只保存摘要。生产环境使用 HTTPS、SMTP；邮件验证码不写响应或日志。角色为 `user`、`admin`；验证邮箱后均可下载已入库资源、提交自己的资源等待审核。管理员兼任发布者和审核员，其提交也不会自动通过。历史 publisher 归一为 user。审核仅接受管理员网页 Cookie，不接受客户端设备令牌。首次管理员通过一次性命令按指定邮箱提升，不自动把首个注册者设为管理员。

客户端使用设备授权流程：本地后端请求 device code，浏览器打开资源中心 `/account` 登录、输入 user code 并批准；本地后端定期查询，获得可撤销的限期访问令牌。用户明确点击“检查登录”或界面按服务端 interval 查询，不能无限高频轮询。账号密码不会经过客户端。设备 code 一次性、短期有效，批准者必须已验证邮箱；过期/拒绝/兑换后不能重放。服务端登录 Cookie 为 HttpOnly、SameSite=Strict，生产为 Secure；所有 Cookie 写请求检查来源。

客户端仅连接管理员通过环境变量配置的资源中心地址，要求 HTTPS（开发仅允许回环 HTTP）；不接受资源包传入 URL，不跟随下载重定向。客户端网页只看登录状态，不获得云端 token；本地权限沿用现有 3DHome 访问策略。已下载资源离线可用。

## 6. HTTP 接口

所有资源 API 位于 `/v1`。异常统一 `{error,code}`，不回传数据库或 SMTP 错误细节。清单摘要随版本返回；服务端作者和时间另置于发布记录，不写回被哈希的清单。

| 接口 | 用途 |
| --- | --- |
| GET /v1/previews/:hash | 读取当前账号可访问的版本预览图 |
| GET /v1/reviews/:hash/preview | 管理员网页查看待审核版本预览图 |
| POST /v1/auth/register、/verify、/login、/logout | 服务端账号流程 |
| POST /v1/auth/resend、/revoke-devices | 重发验证邮件、在账号网页撤销所有客户端授权 |
| GET /v1/auth/me | 当前账号和角色 |
| POST /v1/auth/device | 创建设备授权请求 |
| POST /v1/auth/device/approve | 登录账号批准 user code |
| POST /v1/auth/device/token | 一次性兑换客户端访问凭据 |
| POST /v1/blobs/check | 查询当前账号可复用的摘要 |
| PUT /v1/blobs/:sha256 | 上传并校验对象 |
| POST /v1/releases/auto | 自动同步 `{requestId,manifest}`，服务端事务内分配完整版本和 parent；requestId 为持久 UUID |
| POST /v1/releases | 提交不可变版本，初始状态 pending |
| GET /v1/submissions | 作者自己的提交与审核状态 |
| GET /v1/reviews、/:hash、/:hash/blobs/:blob | 管理员审核列表、清单内容、附件 |
| POST /v1/reviews/:hash | 管理员通过或驳回，记录原因与操作者 |
| GET /v1/resources | 审核通过的公共资源列表、按类型/关键词过滤 |
| GET /v1/resources/:owner/:slug | 资源版本历史 |
| GET /v1/resources/:owner/:slug/:version | 精确版本清单 |
| GET /v1/resources/:owner/:slug/:version/resolve | 已锁定依赖图 |
| GET /v1/blobs/:sha256 | 仅下载审核通过资源引用的对象或自己上传的对象 |

第一阶段为登录可见、审核入库的公共资源中心；待审核和驳回内容仅作者与管理员可见，私有资源/团队共享后续加入；不得用“文件哈希难猜”替代鉴权。

## 7. 存储、部署与验收

PostgreSQL 存放账号、会话、对象归属、版本、审核状态及审核记录；磁盘 CAS 存放字节。备份必须同时包含数据库与对象目录。包文件是用户上传内容，服务器不执行其中脚本，不将其作为 HTML 静态站点直接提供。对象响应为 attachment、nosniff。

测试覆盖邮箱验证与权限、授权码重放/过期、版本不可覆盖、跨账号读取限制、哈希/路径/入口校验、依赖冲突、上传去重、离线安装、副本与绑定隔离、失败不写入。PostgreSQL 实例集成测试与内存 SQL 适配测试要分开标注；本地通过不等于已部署或已完成真实 SMTP 发信验收。

审核状态不参与清单哈希；所有公共版本入口和依赖解析只返回 approved。提交内容不可覆盖，驳回后使用新版本号重新提交。详见服务端 `docs/资源审核工作流.md`。

### 模型标准品信息（可选扩展）

模型清单可携带 product：标准品为 {"isStandard":true,"brand":"品牌","model":"型号"}，非标准品为 {"isStandard":false}。isStandard 必须是布尔值；标准品品牌和型号必须非空且各不超过 120 字符；非标准品不能携带这两个字段。侧栏控件不接受 product。该对象参与清单 SHA256，不改写已提交版本。旧清单缺省表示未标注，不能推断为非标准品。服务端与客户端协议副本同步更新；旧版严格校验客户端可能拒绝含扩展字段的版本。

## 自动同步与内部修订

自动同步请求中的 manifest.version 只能是可见版本。服务端先认证命名空间，再在账号行锁事务中查询 `sync_requests`：同 requestId、同内容返回原提交，异内容返回 409。内容摘要忽略 parent 和内部修订，但包含可见版本、代码、资源资料与图片；与当前最新内容相同也复用原提交。真实变化创建 `可见版本+r.N`，写入数字列 `internal_revision` 用于稳定排序。首次仍为 pending，不自动通过审核。并发同账号请求由 PostgreSQL 行锁串行；单账号不同资源不共享修订序号。

客户端 `resource-center-private/outbox.json` 保存队列与请求 ID，objects 保存已校验的不可变快照。排队不等待远端网络，关闭浏览器后由本地后端继续；失败退避 30–300 秒，重启恢复。后台任务只向排队时指定的中心和账号提交；无配置/首次未登录的任务在首次配置/授权后绑定，不转发其他中心已有任务。退出登录后的已有资源继续保留原账号归属。当前任务失败时，同资源更新等待，其他资源可继续；永久错误需在账号页重试或修改资源后生成替代快照。安装副本默认不启用再次分享；打开开发编辑并保存后才产生新的作者资源。

用户在应用内保存退出触发同步；直接关闭浏览器标签、进程崩溃并不等同于保存退出，未保存修改仍使用离开提醒。已保存入队的快照不受此影响。公共发现列表每个资源只保留最新已通过版本；精确版本与完整已通过版本历史接口继续可用。旧三段版本、清单摘要、审核记录与安装副本保持不变，老客户端不支持新后缀，需客户端与服务端一起升级。
