# HAOS 本地测试加载项

适用于验证尚未正式发布的应用源码。无需创建 Release、打正式标签或上传正式镜像；仍需构建测试容器并重建测试加载项。

建议使用独立的本地测试加载项（独立 slug 和数据目录），备份后导入实例副本，保留正式加载项与数据不动。测试副本应避免重复启动 Node-RED 流程或自动控制真实设备。不要同时复制运行中的私有连接凭据。

将完整测试构建上下文复制到 HAOS 的本地加载项目录（实际路径以主机共享和 Supervisor 版本为准），沿用本项目正式加载项的启动、Ingress、映射及资源限制；测试配置使用独立 slug，移除 image 配置以允许本地构建。仅复制 config.yaml 而缺少 Dockerfile 和源码不能完成测试。

在加载项商店检查更新，再对本地测试加载项执行“重建”。后续源码修改重复复制与重建即可，不需要递增正式版本。不要把已经安装的正式加载项原地改为另一来源，也不要用临时改运行容器文件的方式冒充可重复的 HAOS 更新流程。

验证加载项启动、Ingress 访问、完整实例导入、模型去重、设备与动画、导出再导入和重启后的持久化；确认没有真实控制副作用。失败时停止测试加载项，正式实例继续使用原版本。测试通过后再进入正式构建和发布流程。

来源：[Home Assistant 官方测试说明](https://contributors.home-assistant.io/apps/guides/testing/)。本说明仅定义测试路径，编写文档不代表已经在 HAOS 安装或验证测试加载项。

模型目录更新后的完整备份会包含原先的初始模型。旧版（如 custom.44）不认识新的目录标记及可编辑旧 ID；回退软件时使用升级前的实例备份，不要把新备份直接导入旧版本。
