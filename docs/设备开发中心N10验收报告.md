# 设备开发中心 N10 验收报告

日期：2026-10-01。目标版本：`0.1.5-custom.15`。

## 范围与发布边界

- 旧 `0.1.5-custom.14` 设备开发中心的组件、样式与入口继续保留；新版中心独立存在。冻结哈希和双入口由自动化测试保护。
- 用户负责全部视觉与交互观感验收，开发方不启动浏览器进行视觉验证。
- 用户明确改为先完成 N10 自动化验证并发布新版本，再由用户在自己的 Home Assistant 中测试 Add-on。因此真实 HA 服务调用、Add-on 启动/升级/Ingress 和 N5–N9 最终视觉验收不记为“已通过”。

## 自动化验收

- 新增 `tests/device-development-n10.test.mjs`，以两套隔离临时数据和模拟 HA 实体执行项目新建、设备/实体选择、能力与枚举映射、运行浮窗、3D 外观、控制面板、模拟联调、版本发布、单项目包导出、第二套数据导入、重新匹配、创建新草稿以及旧版本只读检查。测试不会控制真实设备，临时数据在结束时删除。
- `npm test`：140 项通过；`npm run build`：通过。
- `npm audit --omit=dev`：生产依赖零项已知漏洞；修复内容只改变依赖锁定版本。
- 本地 Docker `amd64` 镜像构建通过，镜像标签的版本/架构为 `0.1.5-custom.15` / `amd64`；临时容器内 `/api/health` 与 `/api/device-platform` 均返回 HTTP 200，容器随后停止并删除。真实 Home Assistant Add-on 不由此替代。
- 原有 `8101` 源码服务在重建中发现 Rollup 可选 Linux 原生包偶发缺失。源码 Dockerfile 显式包含可选依赖后重建通过，服务容器恢复健康，原地址 `/api/health` 与 `/api/device-platform` 返回 HTTP 200；原挂载的数据目录没有删除。
- 源码静态核对：模型预览按可见区延迟挂载，卸载时取消动画帧、断开 ResizeObserver、释放控制器、几何体、材质和 WebGL renderer；关键控件已提供语义标签。但没有浏览器实测，响应式布局、键盘可访问性和长时间内存曲线仍需用户视觉/运行验收。

## 待用户验收

- 在现有 Home Assistant 实例安装/升级 `0.1.5-custom.15`，确认容器启动、Ingress、数据保留与回退路径。
- 复核 N5–N9 的视觉与交互，以及整套七步流程在真实 HA 数据上的表现。
- 若真实 HA 的设备/实体功能联调需要实际控制设备，应由用户选择测试设备并明确授权；本次自动化测试未执行真实设备指令。

以上待验事项不作为已通过结论。发现问题时继续在后续修订版本修复，不修改已发布标签。
