# MCP 部署、连接与权限

适用版本：v0.1.5-custom.45。本文描述当前实现；旧版独立客户端密钥和人工批准机制不再作为默认操作流程。

## 使用前提与入口

MCP 是独立 HTTP 服务，不是语音助手，也不会因保存一个 URL 自动安装或启动。正式镜像包含实现，Docker 部署需显式启用；未启用时，主页浮窗显示接口缺失和引导，不影响原有三维展示。Home Assistant App 与 Docker 使用同一正式镜像，MCP 已随镜像提供，无需另装服务；升级3DHome会同步更新MCP代码。

主页工具菜单 → MCP 连接与权限，打开浮窗。点击外部或按 Esc 收起，内部操作不穿透到场景。绿色表示网页管理接口可达且服务开关开启，红色表示关闭、需认证、接口缺失或连接失败，灰色表示检测中。这不是客户端到独立 MCP 端口的连通性检测。

服务可达时可打开同站点 `/mcp-admin` 管理页，配置共用权限、项目／实体／Node-RED tab 范围、上游连接及查看计划。

## Home Assistant App 启用与更新

1. 在App商店刷新仓库并更新3DHome到本版；MCP随同镜像安装／更新，无需单独安装MCP App。
2. 在App配置页打开“启用 MCP 服务”（mcp_enabled），保存。
3. 在App网络设置中，为容器8102/tcp填写一个未占用的宿主端口，例如18112；不需要修改Ingress网页8099端口。
4. 将配置页“MCP 对外端口”（mcp_public_port）设为18112并保存，随后重启App使监听配置生效。这个选项只用于生成地址，不替代Supervisor网络映射。
5. 打开3DHome浮窗，客户端地址为 http://HA主机IP:18112/mcp。Ingress页面的域名不一定等于可达的HA主机IP，可在浮窗保存正确的完整地址。

私有设置保存在App自有 /config/mcp-private，与业务/data分开。正常App升级保留持久挂载；完整迁移、卸载或重装前应创建包含App数据与配置的HA备份。不要只导出3DHome业务JSON就删除App。已有共用权限、URL和上游连接从同一私有目录读取，升级不自动重置。旧版本没有mcp_enabled时默认关闭，不会因升级新增免密监听。

公开端口可自行选择；服务未启用时可以不映射8102/tcp。HA Ingress只代理网页，不能代替独立MCP端口。

## Docker 启用与自定义端口

使用安装仓库的 `docker-compose.release.yml`，在同目录新建 `.env`：

```dotenv
HA3D_MCP_ENABLED=true
HA3D_MCP_PUBLIC_PORT=18112
HA3D_MCP_PORT=8102
```

```shell
docker compose -f docker-compose.release.yml up -d
```

宿主机 18112 映射到容器 8102，客户端填写 `http://主机IP:18112/mcp`。8112 只是缺省宿主端口，若已占用可以换成任意可用端口。修改映射／监听变量后必须重新创建容器，仅 `docker restart` 不会更新 Compose 配置。不要修改网页端口来代替 MCP 端口。

| 配置 | 含义 | 默认 |
| --- | --- | --- |
| HA3D_MCP_ENABLED | 启动独立监听器 | false，显式启用 |
| HA3D_MCP_PORT | 容器内部监听端口 | 8102 |
| HA3D_MCP_PUBLIC_PORT | 客户端使用的宿主端口和地址默认值 | 8112 |
| HA3D_MCP_PRIVATE_DIR | 独立私有配置目录 | Compose 中为 /mcp-private |

私有目录挂载 `./ha3d-mcp-private`，必须位于普通 `/data` 之外；保留它用于升级和恢复。源码开发 Compose 已启用 MCP，网页 8101、MCP 缺省8112。示例端口不代表所有用户必须使用同一端口。

## 配置连接地址

在浮窗填写完整 HTTP(S) 地址并保存，例如 `https://mcp.example.com/mcp`。此值对所有客户端共用并持久化；不允许用户名密码、查询参数或片段。保存仅改变对外展示／提供给客户端的地址，不会修改监听端口、Docker 映射、防火墙或反向代理。

恢复默认后按当前访问主机和部署的公开端口生成 HTTP 地址。使用 HTTPS 反向代理时应显式保存 HTTPS URL，并配置代理到独立 MCP 监听器；管理页仍属于网页服务。不要向 MCP URL 嵌入 Token。

## 权限模式与边界

当前默认免密直连，所有 Agent 使用 `shared-agents` 共用权限，不再分别创建客户端或连接密钥。允许局域网访问，保留同源检查、共用权限、版本、参数和幂等校验。新建共用身份默认拥有当前实现的业务 scopes、项目／tab 通配范围和原有效 HA 实体范围；HA 实体可填写明确 ID，或由管理员显式授权 `*` 以覆盖全部实体；仍须具备对应 HA scope，服务调用继续校验。已有共用权限不会被升级重新扩大。

写入计划在校验后可直接应用，不需额外人工批准；`nodered.trusted` 允许范围内 Function 等可信代码编辑。只把端口提供给可信客户端；业务范围检查不构成运行任意代码的安全隔离，不应直接将免密服务暴露到公网。

HA 连接需在管理页启用，并复用当前项目连接。支持明确范围内的状态读取、灯具基本服务、input_boolean 和初始禁用的静态灯光自动化，不提供任意 HA 管理或宿主机命令。Node-RED 支持 Basic 账号密码和 Bearer；两者均由服务端加密保存，不在状态接口回显。两项凭据留空保留原连接；切换地址或认证模式需重新提供凭据。连接检查仅执行读取，不部署真实流程或控制设备。

## 计划、版本和恢复

Agent 先读取能力与版本，生成计划，调用 changes.validate／changes.inspect，再以唯一幂等键调用 changes.apply。版本冲突应重新读取再生成计划，不复用旧修订号。共用权限修改会使草稿批准失效；应用仍检查最新权限。真实设备动作不支持撤回；Node-RED 恢复不包含完整凭据。

普通实例导入导出不包含 MCP 私有目录、密钥和上游秘密。迁移需在停服后单独备份业务 data、assets 与 mcp-private，私有目录仅保存在可信位置，不提交 Git 或附在公开发布包中。

## 排查

- Docker 报端口占用：调整宿主端口并重新创建容器，再更新客户端地址。
- 管理接口404：确认版本包含 MCP，HA3D_MCP_ENABLED 已启用，日志无启动错误，私有目录在 data 之外。
- 管理页正常但客户端失败：检查客户端到独立端口的网络、URL路径、端口映射及代理；网页绿灯不能证明这条链路可达。
- MCP已关闭：在管理页启用。启动变量为false时监听器根本不会启动，不能仅在管理页解决。
- 保存地址失败：检查管理权限、同源访问、服务版本及URL格式。服务端不替用户探测或请求任意保存地址。
- 权限／范围拒绝：按真实任务授权范围调整，不通过扩大通配或关闭校验绕过。

## 实现与验证

服务端位于 `source/apps/server/src/mcp/`，主页浮窗为 `mcp-connection-guide.jsx`。回归测试使用隔离目录、SDK和模拟上游，不连接真实 HA／Node-RED；正式发布包含这些代码并由 CI 验证，真实上游写入不属于发布测试。

## .43 实体范围与操作规范

HA 实体资源范围支持显式 `*`，管理员保存后覆盖当前及后续实体；与项目和 Node-RED tab 范围分别设置。具体服务和危险动作仍按工具能力校验。侧栏可下载 Home3D MCP 使用 Skill v1.0.0。Node-RED 完整 tab 权限可用 `tabId: "*"` 查看流程页列表。
