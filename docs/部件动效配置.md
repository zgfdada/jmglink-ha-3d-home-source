# 自定义设备部件动效（本地开发版）

入口：设备开发中心 → 打开设备项目 → 3D 外观 → 部件动效。当前版本在本地 8101 验证，尚未发布新的 HAOS 安装版本。

## 准备模型

使用 GLB 或自包含 GLTF。需要单独移动、旋转、显隐或发光的器件应为独立网格或独立父节点；静态外壳可以合并。旋转轴心使用建模时的原点，也可以在规则中设置局部 XYZ 轴心偏移。位移、路径及轴心均使用模型局部单位，GLTF 通常为米；模型整体缩放会一起缩放这些距离。

树形层级路径用于区分同名部件，并保存原始节点名校验身份。更换模型后应重新选部件；选择其他模型会清空旧动效和中文别名。部件树自动将常见节点名显示为中文，未知节点使用“网格部件 / 部件组”编号。选中后可以编辑“部件中文名称”，不会改写模型文件或破坏规则绑定。

## 配置规则

1. 先在能力映射中定义状态、枚举、布尔或数值能力，再选择模型部件并新增规则。
2. 选择能力和触发条件。枚举使用能力的真实原始值，显示其中文标签；数字可使用比较或区间。支持数值连续映射，输入区间线性映射到效果起始值、目标值。
3. 选择位移、角度、持续旋转、缩放、显隐、颜色、发光、路径流光或表面扫光。角度与转速分别为度、度/秒。发光提供常亮、呼吸和闪烁；速度可调。
4. 流光至少需要两个不同路径点，可以填写局部 XYZ，或切换到拾取模式后点击模型表面添加点。光带与光点以叠加方式显示，不要求 UV，不改变原材质。
5. 配置过渡、优先级和条件结束行为。优先级较高的规则覆盖同一部件的同一属性；不要同时选父节点和其子节点。离线、未知或能力缺失时始终恢复原状。
6. 点击“校验并模拟预览”，切换模拟状态、输入数值、暂停、重置或模拟离线。满意后点击“保存规则”，项目外观自动保存；失败会显示错误。修改未保存的规则时，切换标签或开发步骤会阻止离开，需先保存或放弃修改。

模拟只更新当前模型，不调用 HA 服务。规则、中文名称随项目持久化及设备包导出。主页复用相同引擎，从设备已保存的能力映射读取状态或实体属性；需要进一步核对真实实体的状态值与数值范围。

## 车辆充电表面扫光

选择部件树根节点可作用整车，选择「车身」等部件只作用该部分；不需要先拆分车身、不要求 UV、不需要绘制流光路径。新增普通规则并选择「表面扫光」，再选择真实状态能力与原始状态值（例如设备实际提供的 charging）。不绑定特定设备或场景。

车辆充电示例可使用青绿色 `#32efb0`、局部 Z 轴、速度 2（约两秒一轮）、光带宽度 0.22（所选模型轴向长度的比例）、强度 1.8。根据车头方向选择 X／Y／Z，负速度反向，零速度停留在起始相位；宽度支持 0.02–1，强度支持 0–20。确认状态激活、停止和模拟离线的预览后保存。状态结束遵循规则过渡／保持设置；离线或状态不可用时退出扫光。

扫光使用模型表面叠层，保留原材质、遮挡与点击范围，并跟随部件变换。不是场景照明或后期 Bloom，不会把整个车库染成绿色。复杂透明裁切贴图与骨骼动画仍需用实际模型检查效果。

开发人员可在 source 目录运行 `node scripts/build-charging-preview.mjs <输出 HTML 绝对路径>` 生成自包含车辆预览；示例使用同一部件动效引擎，不连接 HA，提供参考／柔和／明亮三种预设与状态、参数调节。

## 范围与兼容

- 当前部件编辑面向上传的 GLB / GLTF；内置整体外形继续使用原有运行预览。
- 每个项目最多 32 条规则，每条最多 20 个部件、32 个流光路径点；中文别名最多 256 个。
- 颜色与发光依赖模型的可用材质通道；通用引擎按实例克隆材质，关闭或重建时恢复原引用并释放动效资源。
- 旧洗衣机专用动画继续兼容；设置通用规则后，通用规则接管该模型的动画，避免重复旋转与整机呼吸描边干扰。
- 支持路径流光与沿模型表面的轴向扫光，不包含任意 UV 纹理流动、骨骼动画编辑、网格拆分或多段时间轴编排。
规则列表每行提供删除，规则设置底部也可删除已保存规则或未保存草稿；删除其他规则前需先处理当前未保存修改。
