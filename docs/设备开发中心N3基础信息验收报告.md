# 设备开发中心 N3 基础信息验收报告

> 执行日期：2026-10-01  
> 节点状态：与 N2 合并待用户视觉验收  
> 设计依据：`2.png`、设计边界规范和重构计划  
> 预览地址：`http://localhost:8101`

## 1. 已实现

- 设备项目卡片“打开项目”、新建后进入独立项目详情。左侧仍仅有“设备项目”和“3D 模型资源库”，旧版中心入口保持不变。
- 项目头部展示模型缩略图、名称、厂商/型号、HA 状态、项目 ID、最后同步时间和关联实体数；有自动保存反馈、导出、复制/删除和定位到绑定区域的入口。
- 七步导航与计划中的后续节点一致：基础信息、能力与属性映射、运行浮窗、3D 外观、控制面板、联调测试、发布。N3 只开放第一步，未实现的步骤给出提示。
- 基础信息包含名称、类型、子类型、厂商、型号和模型缩略图；修改后约 850 ms 自动保存，离开页面或关闭新版中心前先等待保存。
- 设备识别规则支持名称关键词、厂商、型号以及高级关键词、集成来源、实体域和设备类别。规则编辑不会自动改绑设备；只有点击“更新识别绑定列表”才读取最新候选。
- 候选设备与实体分区展示，原绑定保持选中。点击“绑定此设备及所选实体”并在更换设备时明确确认，才提交绑定；服务端校验设备/实体归属和重复占用，并替换同项目旧绑定。
- 已绑定 HA 设备不存在时显示失联提示，保留项目并可重新绑定；临时离线时保留全部配置。绑定记录保存 entity registry ID，HA 实体保留同一 registry ID 而修改 `entity_id` 时自动迁移本地选中项和能力引用。
- 根据首轮用户实测，实体表的勾选框已独立左对齐、ID 列缩短并保留完整 ID 悬浮提示、类型改为中文；增加全选/全不选，以及按住鼠标拖过多行逐行反选（同一次拖动每行只反选一次）。
- 顶部“已绑定实体”只反映持久化绑定，不跟随尚未提交的勾选草稿。旧绑定没有 `selectedEntityIds` 时从已有能力映射恢复，不再把设备全部实体默认勾选；实测原服务目标项目为 4 条能力映射、0 条显式选择。

## 2. 边界与兼容

- 原“开发中心”组件和样式保持冻结；新版页面、样式和业务辅助函数在独立目录。
- 不修改 HA 设备状态、不调用 HA 控制服务。本节点仅在用户明确点击绑定时修改本应用的设备平台绑定记录。自动化写入测试只在临时隔离数据目录执行，不改动 `8101` 运行数据。
- 当前“导出设备包”继续使用旧设备平台备份接口；单设备完整包、冲突策略与发布流程属于 N9。
- 设计图中的“能力模型”和“实体映射”在现行计划中合并为下一步，“运行浮窗”成为单独步骤；因此七步名称按已批准的节点计划实现。
- N2 用户新增规则“设备与家具可同时使用”已同步至计划、代码和测试，覆盖设计附件中旧互斥条款。

## 4. 用户验收操作

1. 刷新 `http://localhost:8101`，点“新版中心” → “设备项目”，打开已有自定义项目或新建测试项目。
2. 核对项目头部、七步导航、基础信息和识别规则。修改规则后，确认当前绑定未自动变化；再点“更新识别绑定列表”。
3. 先检查原项目是否仅预选先前映射的 4 个实体、顶部显示已绑定实体；试用全选/全不选和鼠标拖过多行反选。仅在你允许改动的项目和 HA 设备上点击“绑定此设备及所选实体”，再重新进入确认保存。切换其他设备需确认。
4. 返回项目列表并重新进入，检查自动保存。然后检查 N2 模型卡片的灰/绿“家具”按钮，以及设备/家具用途并存。
5. 点原“开发中心”确认旧版仍可独立使用。完成后反馈 N2、N3 的视觉及交互验收结论，再决定是否进入 N4。
