# 设备开发中心 N2 模型资源库验收报告

> 执行日期：2026-10-01  
> 节点状态：待用户视觉验收  
> 设计依据：`1.png`、`4.png` 及设计文件夹内的边界规范  
> 预览地址：`http://localhost:8101`

## 1. 节点范围与隔离

本节点只开放新版中心的“3D 模型资源库”和“3D 模型配置”。原“开发中心”入口、旧版组件及旧版 CSS 均保留；不新开 `5173` 服务、不清理旧代码、不连接或控制 HA 设备。模型资源继续由原设备平台和在线模型库 API 承载，后端只做向后兼容的字段、校验及上传请求限制调整。

## 2. 已实现

- 统一列出本地与在线模型，提供全部/本地/在线/收藏筛选、名称/标签/作者搜索、排序与在线目录刷新；收藏保存在当前浏览器本地。
- 本地卡片可预览、配置、应用到自定义设备项目；在线卡片可预览、收藏、安装到本地。
- 模型配置包含固定 ID、名称、可选设备模板、标签、GLB/自包含 GLTF 上传、尺寸/缩放/锚点/摆放、离地高度、颜色/粗糙度/金属度、家具开关和家具分类。
- 上传立即解析几何尺寸和材质；预览可旋转、缩放和平移。上传文件限制为 15 MB；模型上传 API 的请求体限制已按 base64 包装放宽到 22 MB。
- 模型卡片只在可见区加载 3D 预览，离开可见区或切换页面时销毁 WebGL 渲染器、控制器和监听器。文件缺失或解析失败时提示错误，配置不丢失。
- 模型卡片在“预览”和“应用到设备”之间增加“家具”使能按钮：灰色未启用、绿色已启用。设备用途与家具用途可并存，切换家具使能不解除设备引用；被设备绑定或项目引用的模型默认仍禁止删除。显式强制删除会解除设备绑定引用，项目保留失效模型 ID，并在项目卡片标记“配置异常”。
- 根据首轮用户视觉反馈，补齐管线机、净水器、燃气热水器和路由器的程序化外形细节；资源库卡片与旧预览/家具栏采用同类造型，不再只显示基础方盒。
- 在线模型按 SHA-256 复用同内容的本地版本；内容变更时生成独立版本 ID，避免覆盖旧模型。

## 3. 验证记录

- 本地完整测试：121/121 通过（与 N3 一起验证）；包含统一集合筛选、设备/家具双用途、项目引用删除保护、在线版本选择、模型上传和删除 API 注入测试。
- 生产构建：通过；Docker 镜像构建中的测试和构建也通过。
- 原 `8101` 容器：重建后健康状态 `healthy`；`/api/health`、`/api/device-platform`、`/api/device-platform/devices`、`/api/model-library/status`、`/api/model-library/models` 与在线模型预览读取正常。
- 原服务静态资源：新版中心 JS 与旧版中心 JS 均返回 HTTP 200；旧版组件和 CSS 哈希保护测试通过。
- 未进行浏览器视觉验证，按用户要求由用户验收。

## 4. 用户验收操作

1. 打开或刷新 `http://localhost:8101`，点击页面原有的“新版中心”。原“开发中心”仍打开旧版。
2. 在新版左侧点击“3D 模型资源库”，核对 `1.png` 对应的标题、工具栏、四个筛选项、模型卡片和预览/收藏/安装/应用操作。
3. 点击“上传本地模型”或本地模型的“配置”，核对 `4.png` 对应的表单、上传、尺寸自动读取和右侧交互预览。
4. 如需验证真实保存/删除，请优先使用新建的测试模型；引用模型的强制删除会改变项目数据，不建议拿已有正式项目试验。
5. 切回“设备项目”，再点击原“开发中心”，确认两个中心均可独立打开且旧版功能不受影响。

## 5. 待验收与边界

- 布局、视觉还原度、交互观感和实际 3D 绘制效果待用户在浏览器中验收；自动化测试和 API 检查不等同于视觉通过。
- 单项目完整七步配置流程属于 N3–N9，本节点“应用到设备”仅更新自定义项目的模型关联；不自动绑定 HA 设备。
- 设计图中若显示 FBX、OBJ、3DS 或更高上传上限，以当前后端真实能力为准：仅 GLB/自包含 GLTF、15 MB；不在界面承诺尚未实现的格式。
- 本节点不发布 Gitea 版本、不提交或推送代码；用户已明确要求 N2 完成后直接开发 N3，两节点合并进行视觉验收。
