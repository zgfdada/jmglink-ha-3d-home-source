# 语音助手配置

## 打开配置

在全屋页面右下角的**麦克风图标上单击鼠标右键**，选择“语音助手配置”。再次右键麦克风可关闭菜单。右键只切换配置菜单，不录音、不发送指令。左下工具栏不增加入口。轻触麦克风仍展开文字输入，长按仍为按住说话、松开发送。

配置界面支持两种执行助手，保存后立即生效，Docker 重启后继续保留。首次部署默认使用 Home Assistant；已有运行配置以保存值为准。

浏览器语音识别与执行助手是两层：当前录入仍使用浏览器 `SpeechRecognition`，识别成文字后再交给所选助手。更换 Hermes 不会解决内置浏览器识别服务的 `network` 错误。可以先用文字验证 Agent，再在支持识别的 Chrome 中测试长按；局域网 IP 的 HTTP 页面可能无法申请麦克风权限，正式访问请配置可信 HTTPS。

## Home Assistant 语音助手

1. 执行助手选择“Home Assistant 语音助手”。
2. 从“HA 助手”选择已配置的管道，或使用“HA 默认助手”。
3. 保存配置，再点击“测试已保存连接”。

使用项目已有的 HA 连接。Add-on 继续由 Supervisor 提供连接，独立 Docker 使用现有 HA 连接配置，无需在此重复填写 HA Token。“测试连接”只读取助手列表，不执行设备服务。页面原有助手选择器仍可临时选择本次指令的 HA 助手，持久默认值在配置区保存。

## Hermes：复用 Telegram Bot 会话

此模式复用已有 Bot 的**同一个聊天／话题、上下文、工具和处理队列**。指令文本会以“来自 3D Home”显示在该 TG 通道，Bot 的最终回复同时出现在 TG 和 3D Home。它不是另开一个 API 会话，也不是通过 Bot 给自己发消息来触发处理。

执行路径：`浏览器转文字 → 3D Home 后端 → 局域网共享网关 → 原 Telegram adapter → 原 Hermes 会话 → 原设备控制工具`。

### 页面配置项

| 配置项 | 填写内容 |
| --- | --- |
| 执行助手 | Hermes · 复用 Telegram Bot 会话 |
| 共享网关地址 | 例如 `http://192.168.31.220:8645`；允许带结尾 `/v1`，系统自动归一化 |
| 网关访问密钥 | 共享入口专用密钥；**不是 Telegram Bot Token，也不是模型 API Key** |
| 网关配置标识 | 当前桥接为 `tghome`；指向该端口所绑定的配置，不能靠修改此项切换到另一个 Bot |
| 等待回复 | 10–300 秒，默认 120 秒；超时可能已经执行，请先查设备和 TG 回复 |

保存后测试连接。测试只访问带鉴权的模型列表，确认共享网关模式，并展示绑定的 Bot 用户名、聊天 ID 和可选话题 ID；不会发送 TG 消息、调用模型或控制设备。普通 Hermes API Server 不提供这里要求的 TG 会话路由，不能用普通 `/v1` 地址冒充共享入口。

密钥保存后不会回显。留空保存会保留旧密钥；需要清除时切回 HA 并勾选清除密钥。配置文件为运行数据目录下 `voice-assistant.json`，包含连接密钥，不进入 Git、项目导出包或普通截图；迁移时通过受保护的运行数据备份处理。服务端写入采用原子替换及 `0600` 权限，Windows 挂载目录还应由本机权限保护。

### 安装共享桥接插件

桥接安装资料和参考脚本可从语音助手配置窗口下载对应的 skill ZIP 包。适用于支持平台插件、`MessageEvent`、Telegram adapter 会话队列及流式 `final_response` 返回的 Hermes；升级 Hermes 后应重跑插件测试，再验证兼容性。

1. 将目录内容复制到**目标 Bot 配置**的插件目录，例如 `/root/.hermes/profiles/tghome/plugins/ha3d-telegram-bridge/`。不要复制到另一个 Bot 配置。
2. 在目标配置 `config.yaml` 的 `plugins.enabled` 列表追加 `ha3d-telegram-bridge`，保留其他插件；在 `platforms` 下追加：

   ```yaml
   ha3d_bridge:
     enabled: true
   ```

3. 在该配置的 `.env` 中设置以下变量，并保护文件权限。密钥至少 32 个字符，使用独立随机值。

   ```dotenv
   HA3D_BRIDGE_KEY=<独立随机密钥>
   HA3D_BRIDGE_HOST=<NAS局域网IP>
   HA3D_BRIDGE_PORT=8645
   HA3D_TG_CHAT_ID=<现有聊天ID>
   HA3D_TG_USER_ID=<Hermes已允许的操作者用户ID>
   HA3D_TG_BOT_USERNAME=<现有Bot用户名，不含@>
   ```

   现有私聊中聊天 ID 与用户 ID 通常相同。群聊必须填写实际群 ID、已授权用户 ID，并设置 `HA3D_TG_CHAT_TYPE=group`；话题还需 `HA3D_TG_THREAD_ID=<实际话题ID>`，必须与现有会话对应，不能仅填写一个 Bot 用户名来指定会话。当前实际联调覆盖私聊；群／话题需另行验证。

4. 仅重启目标配置的网关，例如 `systemctl --user restart hermes-gateway-tghome.service`；实际单元名称以部署为准。不启动第二个 TG poller，不重建原 Bot。
5. 在 Hermes 虚拟环境中运行 `test_bridge.py`。测试使用模拟 TG 和 Agent，不会发送真实消息。
6. 在 3D Home 填写对应地址与密钥，保存并测试；随后先发送“仅回复连接成功，不调用工具、不控制设备”进行实际联调。

桥接只绑定部署时指定的目标，不接收浏览器传入任意聊天、用户或话题 ID。只有通过网关密钥的请求才能以已绑定的操作者身份进入现有 TG 会话，因此应只向可信 3D Home 后端开放，不设置公网映射。不要在浏览器地址或查询参数中携带密钥。

### 并发、失败与回滚

- 长按过程中不发请求，松开后仅提交一次最终文本。前端与后端均禁止本次会话并发执行；TG 原会话忙时桥接返回忙碌，不中断原任务。
- 请求 ID 在 3D Home 与桥接层去重；不自动重试超时、断网、429 或 5xx，避免物理操作重复。去重缓存仅存在进程内，重启会丢失，不能把重新发送当成执行未发生。
- TG 对话、语音指令以及 Hermes 后续执行共用上下文，来自任一入口的新指令都会影响后续对话。TG 连通性和 Hermes 模型额度仍是必要条件。
- 桥接目前拒绝 `/restart`、`/new` 等斜杠管理命令，仅接受自然语言指令。原 TG 内的管理方式保持不变。
- Hermes 流式回复已在 TG 发送时，网页读取 `final_response`；当前网关若返回空值表示已投递，则只读提取同一会话本轮新写入的最终回复，不回读旧轮次，不再发送第二条相同 TG 回复。
- 回滚时先在页面切回 HA；在 Hermes 中禁用 `ha3d-telegram-bridge` 插件及 `platforms.ha3d_bridge`，仅重启该 Bot 网关。原会话与 Bot Token 无需删除或重建。

## 接入 skill 下载包

配置窗口会随当前执行助手显示对应 ZIP 下载链接。解压后将其中同名目录安装到所用 Agent 支持的 skills 目录；包内 SKILL.md 是入口。HA 包包含已有连接的使用说明、后端接入实现、录音提交逻辑和只读连接测试脚本。Hermes 包额外包含实际使用的 Telegram 会话桥接插件及其模拟测试，不含运行密钥。


回答只保留麦克风上方的深色提示框，显示 10 秒后渐出；新的回复会重新计时。右键菜单仅保留“语音助手配置”，再次右键麦克风关闭。


## 选择、补充回答与播报

Hermes 调用澄清工具时，网页会同步显示问题、完整选项按钮及“其他回答”输入框。选择框会一直保留到回答、过期或任务结束，不按普通回复的 10 秒规则淡出。点击选项或输入回答会唤醒原来的等待任务，不创建第二次 Agent 指令。Telegram 与网页共用一个问题；任一端先回答，另一端的选项随状态同步失效，旧问题的按钮不能回答下一道问题。

执行中约每 0.8 秒读取一次状态，读取失败不会重发原指令或自动重试答案。回答期间暂停计算执行等待秒数；Hermes 自身澄清超时仍有效，整次请求最多保留 30 分钟。问题过期或网络异常时先核对 Telegram 及设备状态，不重复发送原设备指令。

v22 起网页通过 `/api/voice-assistant/start` 提交一次任务并立即收到接收确认；后端独立等待 HA／Hermes，网页使用短请求从 `interaction` 读取澄清、最终回复或明确的执行错误。原 `/message` 同步接口保留兼容。每条网页请求最多等待 10 秒，整体等待上限 30 分钟，最终结果在完成后保留 10 分钟；服务进程重启不保留任务记录。

提交响应丢失或返回非 JSON 的 502 时，只查询原请求 ID，不重复提交。进度暂时不可达时保持等待并提示恢复连接；记录丢失、确认执行失败、权限失效或整体等待超时才结束当前等待，并明确提示执行状态未知。澄清答案仍只发送一次，不允许跨终端读取其他请求的结果。

2026-10-21 在 NAS 目标 Bot 日志确认两次查询均正常完成，耗时分别为 17.5 秒和 11.4 秒，没有对应模型或桥接错误；网页截图为 HTTP 失败的通用提示。旧网页需要保持整轮长连接，无法从断开的响应恢复最终结果；本修复移除这项依赖。尚未定位具体哪个代理关闭了用户的连接，不将推测的代理超时值写成已确认事实。验收包含慢回复、提交响应丢失、进度 502、原请求去重及澄清选择，不发送真实 TG 测试消息或控制设备。

在“语音助手配置”勾选“自动语音播报回复与选择问题”，用“播报音量”滑块设置 0–100%，保存后生效。默认关闭，初始预设音量 60%；使用浏览器／系统中文语音，最终响度同时受系统音量影响。相同问题在状态同步中只朗读一次，开始录音会停止播报，避免把扬声器内容再录入。配置为全局设置，对 HA 与 Hermes 都有效。

开发验证可运行 `node tests/fixtures/voice-interaction-demo.mjs`，访问仅绑定本机的 `http://127.0.0.1:18102/`。这是模拟 Agent，所有回答均在内存处理，普通页面只读资源来自 8101；不向 TG 发消息、不调用 HA 写接口。结束时按 Ctrl+C 关闭并清理临时配置。


## 测试连接提示 Unsupported Media Type

这是 HTTP 415 请求格式错误，发生在解析请求时，不能据此判定网关密钥错误。HA Ingress 可能为无请求体的 POST 补上 `application/octet-stream`，后端拒绝后尚未进入网关鉴权。网页测试请求应显式发送 `Content-Type: application/json` 和空对象 `{}`；保存配置及普通对话本身已经使用 JSON。

修正版需同步更新前端，并在 HA 页面强制刷新后再测试。不要因此反复更换密钥；真正的密钥错误会提示“Hermes 网关鉴权失败”。

## 多终端与反向代理来源校验

助手类型、网关地址与密钥保存在服务端运行数据中，各终端登录同一个 HA／3D Home 服务后共用配置，不需要复制浏览器 Cookie 或重新填写网关密钥。录音权限需要在各终端分别允许；交互请求 ID 保持终端独立，避免其他终端误答当前的澄清问题。

v20 及之前仅比较浏览器 `Origin` 与后端 `Host`，在 HA Ingress／反向代理改写 Host 后可能误报“请从当前 3D Home 页面操作语音助手配置”。v21 修复使用浏览器控制的 `Sec-Fetch-Site: same-origin` 判断原始同源请求，不绑定某个域名、Cookie 或首个终端。`cross-site` 和 `same-site` 跨源请求仍拒绝；缺少 Fetch Metadata 的旧客户端仅在 Origin 与 Host 匹配时兼容，不信任任意 `X-Forwarded-Host` 或 Referer。

2026-10-21 在实际 HAOS v20 创建两个独立 Ingress 会话、带两个外部访问域名的 Origin 复现均为 403；同一配置的无 Origin 只读测试为 200，确认来源校验是本次拒绝的原因。修复已加入全部语音写接口、独立客户端请求和运行镜像检查；本地测试不能替代修复镜像升级后的真实终端验收。发布时设置 `HA3D_TEST_ORIGINS` 为以逗号分隔的实际入口 Origin，再运行 `node scripts/verify-ha-ingress.mjs`；脚本会创建独立会话并验证外站拒绝，仅测试网关连接，不发送模型消息或控制设备。
