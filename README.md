# JMGLink HA 3D Home Custom

> 致敬并感谢原作 [JMGLink HA 3D Home](https://gitee.com/tuotuo4ever/jmglink-ha-3d-home) 的原作者及所有贡献者。
>
> 本项目是基于原作的**二次开发作品**，在原有 3D 家居可视化与 Home Assistant 控制能力上继续扩展和维护。

把户型、家具和 Home Assistant 设备放进同一个 3D 家居界面。

本仓库提供当前公开源码；安装和版本下载请使用[安装仓库](https://gitea.700117.xyz:16666/zgf/jmglink-ha-3d-home-custom)。

支持全屋状态查看、设备控制、户型编辑、自定义模型与面板，以及 HA / Hermes 语音助手。可作为 Home Assistant App 安装，也可直接拉取 Docker 镜像独立运行。

**当前版本：`0.1.5-custom.37`** · 支持 `linux/amd64`、`linux/arm64`

## 你可以做什么

当前版本的门磁绑定使用单个可搜索下拉控件：在同一输入框搜索名称或实体 ID，面板内列表实时筛选并换行显示长文本，搜索不会改变已有绑定。兼容 `binary_sensor` 门磁与普通 `sensor` 门状态；中文“门虚掩”“门未关”等状态可联动 2D／3D 门扇。

当前版本的第四个入口「动效资源库」以「代码 + 实时效果」同页维护九种内置动效，可编辑 JavaScript 运动算法与扫光 GLSL 着色代码，校验后更新效果并保存，也支持参数编辑、复制与自定义资源。设备项目复用同一代码与参数快照；现有规则保持独立配置。手机横竖屏隐藏主页「开发与编辑」菜单。详见[动效资源库](docs/动效资源库.md)。

当前版本的设备项目支持在「基础信息 → 额外关联实体」中直接搜索并选择其他设备的传感器、定位跟踪器或人员实体，也支持不绑定自身 HA 设备、仅使用额外实体的独立模型。保存后，在原有「能力与属性映射」配置对应能力，再在「3D 外观 → 部件动效」选择该能力；实体选择页不配置动效。详见[额外实体配置](docs/额外实体配置.md)。

| 模块 | 能力 |
| --- | --- |
| 户型与场景 | 多楼层、墙体、房间、门窗、底图与家具；3D 全屋展示，默认卡通风格 |
| 楼层侧栏 | 按真实楼层生成玻璃楼层栏；各楼层独立设计、保存和发布侧栏，开发中心可切换楼层 |
| 设备控制 | 按 HA 房间发现设备，多实体聚合；灯光、空调及其他设备的状态与能力映射 |
| 模型与家具 | GLB / 自包含 GLTF、本地上传及已安装模型、自定义外观；模型可用于设备或家具 |
| 编辑工具 | 异型柜体、多选复用、对齐吸附、水平基准面；无选中对象时右键平移 2D 画布 |
| 开发中心 | 设备项目、能力映射、面板设计、模拟联调、版本快照与导出 |
| 语音助手 | 轻触输入、长按说话；HA Assist 或 Hermes 原 Telegram Bot 会话，支持澄清选择及回复播报 |
| 数据管理 | 项目导入导出、历史备份、独立设备包；持久化数据与应用镜像分开保存 |

默认侧栏只提供“主页”和天气控件；其他控件及导航通过侧边栏开发中心自行设计或导入，已有自定义布局会保留。

## 选择安装方式

| 方式 | 适合谁 | HA 连接 |
| --- | --- | --- |
| Home Assistant App | 使用 HAOS / Supervisor | 安装后自动连接当前 HA |
| Docker 镜像 | NAS、服务器或 Docker Desktop | 在界面配置 HA 地址与访问令牌 |

两种方式均直接使用已发布镜像，无需在设备上安装开发工具。

## Home Assistant App 安装

1. 在 Home Assistant 的应用商店添加仓库：

   ```text
   https://gitea.700117.xyz:16666/zgf/jmglink-ha-3d-home-custom
   ```

2. 安装 **JMGLink HA 3D Home Custom**，启动后点击“打开 Web 界面”。
3. 在项目中配置户型、房间和 HA 实体绑定。建议先导入或创建项目，再操作设备。

Supervisor 会按主机架构选择镜像，自动连接当前 HA，无需填写长期令牌。运行参数和数据路径见 [部署说明](docs/deployment.md)。

## Docker 镜像安装

镜像地址：

```text
gitea.700117.xyz:16666/zgf/jmglink-ha-3d-home-custom:latest
```

使用仓库提供的 [docker-compose.release.yml](docker-compose.release.yml)，将文件保存到自己的部署目录后执行：

```shell
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

打开 `http://主机IP:8101`，在界面配置 Home Assistant 连接。Compose 中已指定独立运行入口，请不要直接使用 App 默认入口启动独立 Docker。

| 主机目录 | 容器目录 | 用途 |
| --- | --- | --- |
| `./ha3d-data` | `/data` | 项目、绑定、助手配置与其他运行数据 |
| `./ha3d-assets` | `/assets` | 用户模型及素材 |

**从旧 Docker 部署迁移时，先备份，再把 Compose 的主机目录改为原有 `docker-runtime-source/data` 和 `docker-runtime-source/assets`。不要空目录启动后误以为旧项目丢失，也不要让两个容器同时写同一份数据。**

## 部件动效（本地开发版）

3D 外观新增「部件动效」：中文部件树、状态和数值映射、位移／旋转／显隐／颜色／发光／路径流光，支持校验模拟后保存，主页使用相同规则。模拟不控制真实设备。详见[部件动效配置](docs/部件动效配置.md)。

## 内置摄像头与监控

设备列表「已隐藏」数量右侧的「取消隐藏」开关可显示全部尚未摆放的系统／辅助实体，关闭恢复过滤。设备列表提供独立「摄像头」类型，未摆放的 camera 实体不会因同设备辅助开关或传感器而隐藏。提供枪型、球型单摄、球型双摄、桌面型四种内置摄像头模型，可在房间布局编辑的摄像头外形选择中使用，也可在设备开发中心的本地模型库检索「摄像头」后用于设备外观。模型不包含账号或视频地址，使用前绑定真实 HA `camera.*` 实体。

在 3D 主页点击摄像头设备模型即可打开监控弹窗并自动尝试播放：优先使用 HA 提供的实时流，不支持时回退到定时快照。可停止、刷新、点击关闭或按 Esc；关闭后停止视频和快照刷新。手机端自适应。双摄模型可在设备属性中选择第二路 camera 实体，控制面板显示两个缩略图，点击播放打开大浮层，通过居中的「主摄／第二路」标签切换画面。可配置外部访问地址，以及自动检测的 Frigate／ONVIF 云台控制。枪型、球型默认绑定天花板，按模型实际高度及缩放防止穿顶；桌面型保留地面／台面安装。真实画面可用性取决于 HA 摄像头集成与浏览器支持。

## 楼层与面板

左下角悬浮按钮可一键隐藏／显示整块侧边栏和楼层选择栏，手机端收起后只保留小按钮。原有的内容折叠功能仍可使用；重新展开恢复原楼层和侧栏状态，显示选择仅保存在当前浏览器，不修改户型或设备。

通过左侧楼层选择器切换楼层，各层保留独立侧栏。只有一个楼层时隐藏楼层选择区域。设备开发中心的控制面板画布支持滚轮、触屏和键盘滚动，可访问长面板的底部控件。

## 开始使用

1. **连接 HA**：App 自动连接；独立 Docker 在界面配置连接。
2. **准备户型**：创建或导入项目，绘制墙体、房间与门窗，设置实际尺寸。
3. **放置设备**：按 HA 房间发现设备，选择实体并配置能力映射。
4. **配置外观**：使用内置家具或模型库；高级设备可进入开发中心配置外观和面板。
5. **备份项目**：较大修改前导出完整项目 JSON，同时备份持久化目录。

开发中心的模拟联调不会发送 HA 指令；真实控制会改变所绑定设备状态。请按设备实际能力配置控件。

## 语音与 Agent

轻触右下角麦克风输入文字，长按说话；右键麦克风打开“语音助手配置”。

- **HA 助手**：使用原 HA Assist / conversation 接口。
- **Hermes**：连接局域网会话共享网关，复用原 Telegram Bot 的会话、上下文与工具。
- **多终端**：助手和密钥保存在服务端，各终端分别登录并授权麦克风，无需复制 Cookie。
- **选择问题**：在网页点击选项或补充回答，继续原任务；TG 与网页先到的答案生效。
- **回复播报**：可开启自动播报并保存预设音量，开始录音时停止播报。
- **断线恢复**：短请求查询原任务结果，不自动重发指令；记录丢失或结果未知时先检查 TG 与设备状态。

配置窗口提供对应平台的 skill 文档与 ZIP 包。详细步骤、支持范围与排障见 [语音助手配置](docs/语音助手配置.md)。

## 升级与回滚

**升级前：**导出项目 JSON，并备份整个运行数据与素材目录。网关密钥属于受保护的运行数据，不要放入 Git 或公开截图。

### Home Assistant App

在应用商店检查更新，或使用运维页的“刷新应用更新源”，随后升级 App。升级后强制刷新网页。不要通过卸载重装升级，卸载可能删除 App 数据。

### Docker

Compose 默认使用 `latest`，升级时直接执行：

```shell
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

当前公开镜像仅保留 `latest` 和当前版本。升级前如需保留回滚能力，请自行保存原镜像与兼容数据备份。保留挂载目录；不要删除数据卷或运行目录。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 升级后仍是旧页面 | 强制刷新浏览器，确认 App 实际版本 |
| 设备显示离线 | HA 连接、实体是否存在及设备实际状态；`unknown` 与 `unavailable` 含义不同 |
| 换终端后语音不可用 | 各终端登录状态、麦克风权限、HTTPS 与当前版本；不要盲目更换网关密钥 |
| TG 已回复但网页失败 | 升级至包含短请求回复恢复的版本，刷新页面，先确认实际执行结果，避免重复操作 |
| 商店暂未显示新版本 | 手动刷新应用更新源；刷新只检查版本，不自动安装 |
| 8101 端口被占用 | 修改 Compose 端口左侧主机端口 |

### 本地开发中的侧边栏界面

主页展示区内嵌导航；在主页工具菜单进入“侧边栏开发中心”，使用“控件开发”和“页面设计”两页。支持实体绑定、HTML/CSS/JS 卡片、共享渲染预览与草稿发布。详见 [侧边栏开发说明](docs/sidebar-development.md)。当前正式镜像仍为上方标注版本。

运维导航集中显示离线统计及低余量耗材，保留 HA 原显示条件并支持刷新；音乐导航复用 Songloft 音乐中心，支持展开歌词、搜索、歌单和播放列表。

侧边栏控件支持通用 HA 状态订阅和动作 SDK：在开发中心搜索服务、配置动作及绑定实体，随布局保存、导入和发布；新控件无需添加专属后端逻辑。下载的控件设计 Skill 包含最新协议、完整音乐源码与运维样板。

房间控件样板支持五房间切换、灯光总控与模式、双层窗帘模拟开合动画及空调详情；不展示逐灯控制。各房间实体与动作可在控件代码和绑定配置中调整，无需添加专属后端接口。主页默认平面俯视，方向与平面设计一致，支持水平360°旋转并防止翻到地基下方。

### 设计迁移与编辑器

轮廓描边固定为原始粗细的 10%，工具菜单不再提供调整入口。开发入口统一收在「开发与编辑」下，房间编辑入口名称为「房间布局编辑」。

侧边栏开发中心支持导出当前控件、当前导航页（包含引用控件）和整层侧栏；导入控件与页面自动处理 ID 冲突，整层侧栏导入替换当前楼层草稿，保存或发布后才生效。

主页工具菜单「导入导出」可下载完整实例 JSON，包含所有户型、设备/模型资源、设备编辑记录、控件库和各楼层侧栏草稿与发布布局。空安装选择备份后，再确认替换即可恢复；导入前自动保留业务数据备份。HA/Hermes 地址、密钥及登录设置不迁移，恢复后需要重新连接，并核对实体 ID。外部 URL 资源仍需原地址可访问。文件上限 128MB。从 v0.1.5-custom.30 起提供。


可选事件与运维控件：事件直接读取原移动端通知日志；主机资源展示整机 CPU、内存和已用/可用数值；离线统计及待补充耗材可独立放置。配置与使用见[侧栏开发说明](docs/sidebar-development.md)。本版本已提供样板生成器，不会强制添加到现有侧栏。

在线模型功能正准备重新设计，本版本已移除在线页面及接口；本地模型、已安装资源和既有设备引用保留。此变更已发布。

内置控制面板控件为 12 项，升级保留自定义控件与既有面板快照。HAOS 更新说明通过 App 目录 CHANGELOG.md 提供。正式交付不含本地教程和愿景演示素材。
